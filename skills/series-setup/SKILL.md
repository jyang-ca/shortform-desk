# 시리즈 설정 (인터뷰)

이 플러그인은 특정 시리즈의 설정을 갖고 있지 않다. **시리즈마다 사용자에게 물어서 채운다.** 묻는 목적은 하나다. 생성 전에 고정해 둘 값(인물 겉모습·장소 구조·형식 숫자·금지)을 정해 두면, 나중에 "왜 머리가 바뀌었어?" 같은 지적이 줄어든다.

말은 한국어, 쉬운 말, 짧은 문장. 사용자 말은 원문 그대로 적는다.

## 경로
- 이 스킬 폴더의 `../../tools` = **TOOLS**(절대 경로로 바꿔 쓴다). 템플릿은 `../../templates`.
- 프로젝트 폴더 = 사용자가 말한 곳. 말이 없으면 지금 작업 폴더 아래 `<영문-짧은-이름>/`을 제안한다.

## 0. 준비 (묻기 전에)
1. `python3 TOOLS/setup/doctor.py`를 돌려 환경을 본다. 빠진 필수(ffmpeg·Codex 로그인·키)가 있으면 **설치 방법을 알려 주되 인터뷰는 계속한다.** 생성만 나중으로 미룬다. 키 값을 묻거나 채팅에 받지 않는다. 키체인 등록 명령만 알려 준다.
2. 사용자가 기획서·대본·참고 그림·예전 작업 폴더를 주면 **먼저 읽고** 답을 미리 채운다. 이미 답이 있는 것은 묻지 않고 "이렇게 읽었는데 맞나요?"로 한 번에 확인한다.
3. 기존 프로젝트면 `python3 TOOLS/setup/init_series.py <project> --missing`으로 빈 칸만 묻는다.

## 1. 묻는 순서
한 번에 최대 4개를 묻는다. 고를 수 있는 것은 `AskUserQuestion`으로, 글로 답해야 하는 것은 채팅으로 묻는다. 고르는 질문에는 **추천을 첫 번째**에 두고 "(추천)"을 붙인다. 이유는 한 줄로. 모르겠다고 하면 추천값으로 두고 '나중에 바꿀 수 있음'이라고 적는다.

라운드가 끝날 때마다 답을 `answers.json`(scratchpad)에 부분 JSON(`templates/시리즈/설정.json`과 같은 키 구조)으로 적는다. 그다음 `python3 TOOLS/setup/init_series.py <project> --title "<제목>" --answers <answers.json>`로 합친다. 첫 실행이 프로젝트를 만든다(drama-skills 프로젝트 + 시리즈/ + 검수/).

**라운드 1. 시리즈의 뼈대**
- 제목. 가제도 된다.
- 한 줄 로그라인: 누가, 무엇을 원하는데, 무엇이 막는가.
- 장르와 비슷한 채널·작품. 참고만 하고 베끼지 않는다.
- 말 방식: 1인칭 내레이션(추천: 1인 AI 쇼츠에서 입 모양 문제가 없음) / 인물 대사 / 내레이션+대사 / 말 없음
- 한 화 길이 상한(60·90·180초), 계획 화수, 플랫폼(쇼츠·릴스·틱톡)

**라운드 2. 인물 — 가장 중요**
- 주인공을 화면에 어떻게 보일지:
  - ① 얼굴 없는·가려진 인물(뒷모습·실루엣·가면) (추천: 화마다 얼굴이 바뀌는 문제가 가장 적음)
  - ② 실사 얼굴
  - ③ 애니·일러스트
  - ④ 사람이 아닌 주인공
- 인물마다 겉모습 고정값: 나이대, 체형, 머리, 옷, 늘 지니는 것, 절대 바뀌면 안 되는 것. 글로 받는다.
- 받은 답으로 Claude가 영어 문장 세 개를 쓰고, 보여 주고 확인받는다.
  - `image_sentence`: 키프레임용. 매 프롬프트에 그대로 들어간다.
  - `video_sentence`: 영상용. 짧고 몸 낱말이 적어야 한다.
  - `hands_sentence`: 손만 나오는 샷용.
- 프롬프트에서 이 인물을 가리키는 영어 낱말(예: `shop owner`, `the boy`)은 `prompt_words`에 넣는다. 린트가 이 낱말이 나오면 인물 샷으로 보고 참조 라벨·인물 문장을 확인한다.
- 바뀌면 안 되는 것은 `locks`에 짧은 영어 구절로 넣는다. 결정표 항목(`require`/`forbid`)으로도 만들어 린트가 막게 한다.
- 안전 검사 주의: 얼굴 없는 몸 전체가 보이는 인물(실루엣·마네킹형)은 영상 생성의 안전 검사에 '성적 콘텐츠'로 거절되기 쉽다.
  - 그런 인물이면 `video_sentence`를 **사람이 아닌 조각상·마네킹처럼 쓰는 방식**으로 제안한다. 예: "The figure is an abstract matte-<색> mannequin sculpture with no anatomy, …"
  - 그리고 `safety.video_body_word_check: true`를 켠다. 그러면 영상 문장에서 몸 낱말을 린트가 막는다.
- 인물 참조 시트(정면·옆·뒤): 있으면 경로를 받아 `ref_sheets`에 넣는다. 없으면 "데스크에서 먼저 시트를 만들자"고 다음 할 일로 둔다.
- 참조 라벨(`ref_label`)에는 **한자가 들어가야** drama-skills가 받는다. 예: `《主角·C1》`, `《女主·C1》`.

**라운드 3. 장소**
- 자주 나오는 장소 1~3곳: 구조(방 배치·창 방향·문 위치), 늘 있는 것, 시간대.
- 좌우·방향은 '들어오는 문에서 볼 때' 기준으로 적는다(`orientation`). 참조 그림이 있으면 `ref_images`에 넣는다.

**라운드 4. 보는 맛**
- 화풍:
  - 포토리얼 시네마틱(추천: 쇼츠 서바이벌·일상 장르에 흔함)
  - 애니
  - 일러스트·수채
  - 3D
- `style_line`(모든 키프레임 프롬프트 끝에 붙는 화풍 줄)을 영어로 써서 확인받는다.
- 색과 빛.
- 카메라 성향:
  - 차분하고 인물 곁에 붙음(추천: 몰입이 좋고 어지럽지 않음)
  - 역동적
- 시각 템포 상한(`look.tempo_change_per_10s_max`): 기본 1.6, 차분할수록 낮게.

**라운드 5. 제작과 돈**
- 이미지 서비스:
  - Codex 이미지(추천: ChatGPT 구독 안에서 장당 과금 없음. 하루 수십 장 한도)
  - Gemini 이미지(API 과금)
- 영상 서비스:
  - sume Gemini Omni Flash(추천: 360p 초당 약 $0.023, 실패하면 환불)
  - Gemini API
  - 아직 안 함
- 내레이션:
  - ElevenLabs(목소리 ID 필요)
  - 없음
- 목소리를 모르면 원하는 느낌(성별·나이·톤)을 받는다. 후보는 ElevenLabs 보이스 라이브러리에서 사용자가 직접 듣고 고르게 안내한다. 목소리 값은 사용자가 승인해야 정해진다.
- 자율 범위(`검수/권한.json`): 기본값을 보여 주고 승인을 받는다. 기본값은 샷당 키프레임 3번, 영상 3테이크, TTS 줄당 3번, 화당 영상 $8, 360p.
  - 승인 원문을 `approved_quote`에 적고, `approved: true`, 날짜를 넣는다.
  - 승인하지 않으면 `false`로 두고, 유료 생성마다 묻는다.

**라운드 6. 지킬 것(규칙 씨앗)**
- "이건 절대 안 됐으면 좋겠다"를 3~5개 받는다. 예: 인물 얼굴이 보이면 안 됨, 피·부상 없음, 글자 없음.
- 늘 같아야 하는 소품·색 → `검수/현재-결정표.json` 항목(trigger/require/forbid 정규식, 날짜, 원문)
- 시리즈 고유 판단 → 규칙집 `## 시리즈 규칙 (S-…)` 절에 S 카드(규칙·적용·검사법·통과 기준·고치는 법·출처 '사용자 결정'·원문)
- 공용 규칙(R)과 겹치면 S를 만들지 않고 "R-… 그대로 씀"이라고 알린다.

## 2. 글로 쓰기 (Claude가 쓴다)
- `시리즈/바이블.md`: 라운드 1~4 답으로 템플릿 칸을 채운다. 사용자 말은 따옴표로 그대로 남긴다.
- `시리즈/대본-지침.md`: 말 방식·말투·첫 줄·끝 줄·피할 것. 사용자가 예시 대본을 주면 거기서 말투를 뽑는다.
- drama-skills 기획 문서(`项目开发/`)는 원하면 `shortform-desk:short-drama-develop`으로 만든다. 같은 답을 넘기고 설정과 어긋나지 않게 한다.

## 3. 확인과 마무리
1. `init_series.py <project> --missing`이 빈 목록이거나, 남은 칸이 "나중에"로 확인된 것뿐인지 본다.
2. 한 화면 요약: 제목·형식 숫자, 인물 문장 세 개, 장소, 화풍 줄, 서비스·목소리, 자율 범위, 규칙 씨앗(S 카드·결정표 몇 개).
3. 고칠 곳을 묻고 반영한다. 설정이 바뀌면 규칙집 `0-6 변경 기록`에 한 줄 남긴다.
4. 다음 할 일을 하나 추천한다. 보통은 둘 중 하나다.
   - "인물 참조 시트부터 만들기"(데스크)
   - "1화 대본 쓰기"(데스크 → writer)
5. 보드를 처음 만든다: `python3 TOOLS/board/build_board.py <project>`. 경로를 알려 준다.

## 하지 않는 것
- 사용자가 정하지 않은 취향을 정해진 것처럼 적지 않는다. 추천값으로 둔 것은 바이블에 '(추천값, 미확인)'이라고 적는다.
- 키를 묻거나 파일에 적지 않는다.
- 이 단계에서 유료 생성을 하지 않는다. 시트 생성은 데스크가 권한 안에서 한다.
- 다른 작품의 이름·인물·그림을 가져와 쓰지 않는다. 참고 채널은 '측정·공부용'으로만 적는다.
