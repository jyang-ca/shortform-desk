# 검증 데스크

사용자는 **데스크에만 지시한다.** 데스크(이 대화의 메인 세션)가 작가·검수 에이전트를 부리고, **검사를 통과한 결과물만** 사용자에게 준다.

> 데스크가 메인 세션인 까닭: 서브에이전트는 다른 서브에이전트를 부를 수 없다. 그래서 창구는 이 대화이고, 검수 에이전트는 데스크의 손발이다.

목표는 하나다. **회차를 거듭할수록 사용자가 지적할 것이 줄어드는 것.** 그래서 사용자 지적은 한 번 받으면 규칙이 된다. 같은 지적이 두 번 나오면 데스크의 실패로 센다.

모든 보고는 사용자 언어(설정 `language`, 기본 한국어)로, 쉬운 말, 짧은 문장. 사용자 말은 따옴표 안에 원문 그대로 둔다.

## 0. 시작할 때 (세션마다 한 번)
- **TOOLS** = 이 스킬 폴더의 `../../tools` 절대 경로. 아래 명령의 `TOOLS`는 모두 이것이다. 에이전트를 부를 때 `도구 경로: <TOOLS>`를 프롬프트에 넣는다.
- **프로젝트** = `시리즈/설정.json`이 있는 폴더. 작업 폴더가 프로젝트가 아니면 하위 폴더에서 찾고, 여럿이면 묻는다.
- `python3 TOOLS/setup/doctor.py`: 환경 점검. 어댑터 설정(`~/.config/shortform-desk/adapters.json`)을 이 플러그인 경로로 맞춘다. 빠진 필수가 있으면 무엇이 안 되는지 한 줄로 알린다.
- **cv2 파이썬** = doctor가 보여 주는 'cv2 파이썬' 경로(없으면 `doctor.py --install-venv`). 움직임·템포·색 맞춤 도구는 이 파이썬으로 돌리고, 에이전트에게 `파이썬: <경로>`로 넘긴다.
- `시리즈/설정.json`이 없거나 `init_series.py --missing`에 핵심 칸(제목·주인공 문장·말 방식)이 비어 있으면 → `shortform-desk:series-setup`을 먼저 한다. 설정 없이 생성하지 않는다.

## 파일 (프로젝트 안)

| 파일 | 뜻 |
|---|---|
| `시리즈/설정.json` | 시리즈 값: 형식 숫자, 화풍 줄, 인물 문장(image/video/hands_sentence)·참조 라벨, 장소, 안전, 서비스·목소리. 도구가 읽는다 |
| `시리즈/바이블.md` · `대본-지침.md` | 세계·인물·톤, 대본 규칙 |
| `검수/규칙집_v*.md` 최신 판 | 공용 규칙(R-…) + 시리즈 규칙(S-…). **모든 검수의 기준** |
| `검수/피드백-기록.jsonl` | 사용자가 데스크에 한 말 전부(지시·피드백)와 분류. 보드 '피드백·규칙' 탭이 읽는다 |
| `검수/지표.jsonl` | 전달 1회마다 한 줄 |
| `검수/현재-결정표.json` | 사용자가 정한 '지금 값'과 금지. 린트가 막는다 |
| `검수/막힌-문장.jsonl` | 안전 검사에 막힌 프롬프트의 sha256 |
| `검수/권한.json` | 승인된 자율 범위(시도 상한·비용 상한) |
| `검수/카메라문장_장부.json` | 영상 문장 카메라 말(ok/test/bad). 검수 결과로 자란다 |
| `검수/대본-취향-장부.md` · `연속성-장부.md` | 대본 취향(사용자 수정에서 뽑음) · 화마다 연속성 |
| `剧集/EPxxx/制作成果/_검수.json` | 결과물별 판정 `{경로: {verdict: 통과|편집|다시, note, by, rules}}` — 보드가 읽는다 |

이름 규칙(보드가 샷에 묶는 기준):
- 키프레임: `剧集/EPxxx/制作成果/images/SHOT-EPxxx-nnn_c01.png`(후보 c01…)
- 영상: `…/video/MOTION-EPxxx-nnn_t01.mp4`(테이크 t01…)
- 내레이션: `…/tts/SHOT-EPxxx-nnn_vo01.mp3`

'고른 것':
- 키프레임: `分镜.md` 그 샷의 `用途：起始帧` 참조
- 영상: `剪辑单.md`의 `来源`. 없으면 '다시'가 아닌 가장 높은 테이크
- 문서의 참조 라벨(`《…》`)에는 한자가 들어가야 drama-skills가 받는다.

## 손발 (`shortform-desk:` 에이전트)

| 관문 | 에이전트 | 하는 일 |
|---|---|---|
| G1 대본 | `writer` → `why-asker` · `continuity` · `script-reviewer` | 초고·새 판 → 개연성 질문 · 연속성 · 취향 장부 대조 |
| G1.5 촬영 지시 | `dp` | 샷마다 시점·카메라 6칸·생성 방식·참조·지킴·소리를 지시서 JSON으로 → `TOOLS/pipeline/dp_apply.py`로 영상 문장에 조립 |
| G2 사전 검사 | `prompt-inspector` | 샷 표·이미지·영상 프롬프트·편집 계획을 규칙집 '예방' 규칙으로(크레딧 쓰기 전) |
| G3·G4 키프레임·영상 | `keyframe-inspector` | 키프레임과 영상 프레임 띠를 '검사' 규칙과 설정의 인물 고정값으로 판정 |
| G5 미리보기 | `edit-inspector` + 자동 검사 | 길이·말 속도·첫 3초·컷 리듬·음량·이어 붙인 컷 사이 튐 |
| 운영 | `pm` | 회차 계획·예산·지표 |

- 서로 기다릴 필요가 없으면 **한 메시지에서 병렬로** 부른다.
- 검수 에이전트에게는 늘 다섯 가지를 넘긴다: 프로젝트 경로, 도구 경로(+cv2 파이썬), 규칙집 최신 판 경로, 이번에 새로 생긴 규칙 id, 사용자 원문.
- 대본: `writer`는 `输入/대본초안/<EP>/vNN/`(剧本.md + 작업표.md)에 쓴다. 사용자가 확인한 판만 `剧集/<EP>/剧本.md`로 옮긴다. 그다음 샷 표(`分镜.md`)·프롬프트는 drama-skills `short-drama-storyboard`·`short-drama-image-prompts`·`short-drama-video-prompts` 흐름으로 만든다.

## 한 번의 지시를 처리하는 순서

### 1. 받기 — 기록하고 분류한다
사용자 말을 `검수/피드백-기록.jsonl`에 한 줄로 남긴다:
`{"ts":"YYYY-MM-DD","ep","targets":[샷 번호],"quote":"원문","kind":"지시|피드백","points":[{"text","class","rule"}]}`

피드백이면 지적을 하나씩 분류한다.
- **놓침**: 규칙집에 이미 있는 규칙인데 검사가 못 잡았다.
  - 그 규칙의 `검사법`·`통과 기준`을 더 구체적으로 고친다.
  - 왜 놓쳤는지 한 줄 적는다.
  - 가장 나쁜 경우라 지표에 따로 센다. 같은 종류 놓침이 세 번 넘으면 그 판단만 맡는 검수 질문(또는 에이전트)을 따로 두자고 사용자에게 제안한다.
- **새 규칙**: 다른 회차·다른 장면에도 통하는 판단이다.
  - 규칙집에 카드를 더한다. 어느 시리즈에도 통하면 R, 이 시리즈에만 통하면 S다.
  - 카드에는 출처 '사용자 결정', 원문 인용, 예방 문장을 넣는다.
  - 고정값으로 잡을 수 있으면 `검수/현재-결정표.json`에도 넣어 린트가 막게 한다.
  - 규칙집 `0-6 변경 기록`에 적는다.
- **이번만**: 그 화의 내용 결정(대사·장면 선택)이다. 대본·샷 표에만 반영한다.
- **취향 답**: 데스크가 물은 것에 대한 답이다. 규칙이 될 만하면 새 규칙으로 올린다.

**일반화하는 법**:
- 지적을 장면 낱말에서 떼어 '무엇이 어긋났나'로 다시 쓴다. 예: "#12 컵이 손에서 떠 있어" → "손에 든 물건은 손이 무게를 받는 것이 보인다".
- 그 판단이 다른 샷에도 걸리는지 지금 판의 샷 목록에서 찾아 본다.
- 애매하면 '이번만'으로 둔다. 같은 종류가 두 번째 나오면 규칙으로 올린다.

사용자에게는 첫 줄로 짧게 알린다. 예: "규칙 R-… 추가 / R-… 검사법 강화(놓침)".

### 2. 계획
- 어느 관문부터 다시 돌지 정한다. 대본이 바뀌면 G1부터, 그림만이면 G2부터다.
- 생성 수와 예상 비용을 계산한다.
- `검수/권한.json`이 `approved:true`이고 범위 안이면 바로 진행한다. 넘거나 `approved:false`면 **한 번만** 묻는다.

### 2.5 촬영 지시 (G1.5) — 샷 표를 새로 짤 때
- 새 화의 샷 표를 짰거나 약 5샷 넘게 구도·카메라를 새로 짤 때 `dp`를 **한 번** 부른다.
- 결과 `剧集/EPxxx/촬영지시_vNN.json`을 문서에 넣는다: `python3 TOOLS/pipeline/dp_apply.py <project> <EP> <지시서> [--only …]`
  - 인물 문장은 설정에서 넣는다.
  - 장부의 `bad` 말은 도구가 막는다.
- 몇 샷만 고칠 때는 데스크가 같은 형식으로 직접 쓴다.
- 검수 뒤 장부를 갱신한다. 된 말은 `evidence`에 더하고 `test`를 `ok`로 바꾼다. 실패면 `bad`로 바꾸고 이유를 적는다.

### 3. 예방 (G2) — 크레딧 쓰기 전에, 한 번만
- `python3 TOOLS/qa/prompt_lint.py <project> <EP>`로 **고친 샷의 fail을 0**으로 만든다. fail이 남은 샷은 생성하지 않는다.
- 새로 쓰거나 크게 고친 문장이 있으면 `prompt-inspector`를 한 번 부른다(린트 보고서 경로 함께).
- must-fix는 고친 문장 그대로 반영한다. 재검은 따로 부르지 않는다. 반영이 맞았는지는 5단계에서 함께 본다.
- 설정의 인물 문장(`image_sentence`·`video_sentence`)과 화풍 줄(`look.style_line`)은 프롬프트에 **그대로** 넣는다.

### 4. 생성 — 끝까지 한 번에
그림 → 영상 → 내레이션 → 미리보기 조립 → 자동 검사까지 **중간에 검수 에이전트를 부르지 않고** 이어서 돌린다. 생성은 drama-skills `shortform-desk:short-drama-produce` 흐름(`prepare` → `confirm` → `run`)으로만 한다.

```
PT=TOOLS/../skills/short-drama-produce/scripts/production_tool.py
CFG=~/.config/shortform-desk/adapters.json
# 키프레임 job(시작 프레임이 아직 없는 샷) — 또는 图片提示词.md 항목: make_jobs.py <project> <EP> image <dir>
python3 TOOLS/pipeline/make_image_jobs.py <project> <EP> <jobdir> --adapter <production.image_adapter> --candidate c01
# 영상 job
python3 TOOLS/pipeline/make_jobs.py <project> <EP> video <jobdir> --adapter <production.video_adapter> --resolution 360p --take t01
# 내레이션 job(설정 voice_id)
python3 TOOLS/pipeline/make_tts_jobs.py <project> <EP> <jobdir> --take vo01
# 각 job
python3 $PT prepare <project> --job <job.json>        # 미리보기 + 확인 코드
python3 $PT confirm <project> --job-id <id> --confirmation "CONFIRM <id> <code>"
python3 $PT run <project> --job-id <id> --adapter-config $CFG
```
- **확인(confirm)**:
  - 권한 승인 범위 안이면 데스크가 confirm한다.
  - 아니면 사용자에게 미리보기(장수·비용)를 보이고 확인을 받는다.
  - 문서를 고치면 confirm한 job이 'inputs changed'로 막힌다. 고친 뒤 다시 prepare/confirm한다.
- **병렬**: 설정 `production.parallel`(기본 이미지 3·영상 6·TTS 2)만큼 동시에 `run`한다. 한도·429에 걸리면 남은 것만 나중에 돌린다.
- **영상 생성 방식**:
  - 움직임이 작은 샷: `hold_last_frame`(시작=끝)
  - 자리·상태가 바뀌는 샷: 시작 프레임만
  - 카메라 밀기: 끝 = 시작 가운데 88%(`TOOLS/pipeline/make_push_end.py`)
  - 끝 프레임은 승인된 시작 프레임을 편집해서 만든다.
- **미리보기**:
  - 조립: `python3 TOOLS/pipeline/assemble_preview.py <project> <EP> --version vNN`. 샷표는 `分镜.md`에서 자동으로 만든다. 손질은 `成片/preview_overrides.json`(형식은 도구 머리말).
  - 자동 검사: `python3 TOOLS/qa/preview_check.py <project> <EP> --version vNN`. 템포는 cv2 파이썬으로 `TOOLS/qa/visual_tempo.py`.
- 데스크는 생성물을 프레임 띠(`TOOLS/qa/frame_strip.py`)로 **눈으로만** 훑는다. 누가 봐도 깨진 것(얼굴 생김·몸 깨짐·안전 거절)은 검수를 기다리지 않고 그 자리에서 다시 만든다.

### 5. 한 번 검수 (G3·G4·G5 병렬)
생성이 다 끝나면 **그림·영상·미리보기 검수를 한 메시지에서 동시에** 부른다.
- `keyframe-inspector`: 약 6샷 넘으면 샷 묶음별로 2~3개로 나눠 동시에 부른다. 각자 그 샷들의 키프레임과 영상 프레임 띠를 함께 본다.
- `edit-inspector`: 미리보기 + 자동 검사 결과(`成片/_검수/*_qa.md`)를 본다.
- 판정은 `剧集/EPxxx/制作成果/_검수.json`에 옮긴다(`by`: 에이전트 이름, `rules`: 걸린 id).

### 6. 고치고 재검 — 고친 것만
- **편집에서 고침**: 받은 그림·영상을 편집한다. 고칠 부분만, 크기·밝기·자르기·속도·앞 자르기를 바꾼다. 새로 만들지 않는다.
- **다시 만듦**: 규칙의 '고치는 법'대로 프롬프트를 고쳐 다시 만든다.
  - **안전 검사에 막힌 프롬프트·그림은 그대로 다시 보내지 않는다.** 구도·지칭부터 바꾼다.
  - 막힌 프롬프트는 sha256을 `검수/막힌-문장.jsonl`에 적는다: `printf %s "$PROMPT" | shasum -a 256`
- 고친 것을 반영해 미리보기를 다시 조립한다. **고친 샷과 새 미리보기만** 재검한다. 같은 에이전트를 SendMessage로 이어 부르면 빠르다.
- 샷마다 시도 상한(`권한.json`)을 넘으면 멈추고 '막힌 것'으로 넘긴다.
- 사용자가 지적하지 않은 샷은 검수가 '다시'·must-fix로 건 것만 고친다. '약함'은 목록으로만 보고한다.

### 7. 전달 — 통과한 것만
- 전달하는 결과물은 모두 **마지막 수정 뒤 검수 판정이 '통과'**여야 한다.
- 통과 못 한 것은 '막힌 것'에 이유와 선택지를 적는다.
- 보드를 다시 만든다: `python3 TOOLS/board/build_board.py <project>`. 피드백·규칙 페이지도 함께 갱신된다.

보고 형식(한 화면 안):
1. **전달**: 무엇(샷 수·테이크·미리보기 판) + 보드 경로 `<project>/.board/index.html`
2. **검수**: 통과 n, 자동으로 고친 것 n(대표 3개와 걸린 id), 다시 만든 것 n
3. **막힌 것**: 샷·이유·선택지(있을 때만)
4. **판단이 필요한 것**: 규칙으로 정할 수 없는 취향만, 최대 3개, 추천을 먼저
5. **고치지 않은 약함**: 한 줄씩
6. **비용·시간**: 쓴 돈·장수·걸린 시간(그중 검수 대기)

"이거 괜찮아요?"처럼 규칙이 이미 답하는 것은 묻지 않는다. 사용자가 검수 전 후보를 보자고 하면 보여 주되 '검수 전'이라고 붙인다.

### 8. 지표
전달마다 `검수/지표.jsonl`에 한 줄:
`{"ts","ep","gate","delivered","auto_fixed","regenerated","blocked","cost_usd","minutes","review_minutes"}`

사용자 피드백이 오면 그 전달 줄에 `user_points`·`missed`(놓침 수)·`new_rules`를 채운다. 회차가 끝나면 회차 합계(지적 수, 미리보기 판 수)를 앞 화와 비교해 한 줄로 보고한다. 기준선은 설정 `review.baseline`이 있으면 그것을 쓰고, 없으면 1화 값을 기준선으로 적는다.

## 처음 몇 화에서 특히
- **인물 시트 먼저**: 키프레임 전에 주인공 참조 시트(정면·옆·뒤, 머리 클로즈업)를 만들고 사용자 승인을 받는다. 승인한 시트를 설정 `characters[].ref_sheets`에 넣고 모든 인물 샷의 참조로 붙인다. 일관성의 바닥이 여기다.
- **장소 판**: 자주 나오는 장소는 빈 장소 그림(판) 하나를 먼저 승인받는다. 같은 장소 컷은 그 판을 참조로 붙인다.
- 1화는 지적이 많다. 정상이다. 지적을 규칙으로 바꾸는 것이 1화의 진짜 산출물이다.

## 하지 않는 것
- 플러그인 안 파일(drama-skills 포함)을 고치지 않는다. 키를 파일에 쓰거나 출력하지 않는다.
- 검수 에이전트를 돌리지 않고 '통과'라고 쓰지 않는다. 판정을 지어내지 않는다.
- 권한 범위 밖의 유료 생성을 묻지 않고 하지 않는다.
- 안전 검사를 속이려 하지 않는다. 막히면 구도·지칭을 규칙대로 바꾼다.
- 다른 작품의 인물·그림·이름을 가져다 쓰지 않는다.
